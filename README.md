# Polyglot Concordance

> ⚠️ **This is a pilot.** Current scope is the Gospel of Mark only. The full plan — additional NT books, the Hebrew Bible flagship, further witnesses, export formats, and two planned sub-projects — lives in [**ROADMAP.md**](./ROADMAP.md).

A concordance initiative with alignment to the word level — the **Gospel of Mark** across three textual witnesses (**Greek NT**, **Syriac Peshitta**, and **Latin Clementine Vulgate**), with a one- or two-sentence critical apparatus on every divergence. Multilingual UI in **English, Spanish, Simplified Chinese, and Traditional Chinese**, plus a public read-only **JSON API**.

The apparatus is generated by Anthropic Claude Sonnet 4.5, pre-computed as static JSON, and served by a small Flask app. **No runtime LLM calls.**

> 🔗 **Live:** [polyglotconcordance.com](https://polyglotconcordance.com) · API: [/api/v1/](https://polyglotconcordance.com/api/v1/) · API docs: [/api/docs](https://polyglotconcordance.com/api/docs) · run locally at [localhost:5020](http://localhost:5020) (see [Quickstart](#quickstart)).

---

## What it does

- **678 Mark verses aligned word-by-word** across three traditions, every verse classified, every divergence typed and annotated.
- **Three view modes per verse**:
  - **Interlinear** — stacked rows, one group of aligned tokens per slot
  - **Alignment grid** — Chen-style parallel columns, one row per alignment group
  - **Critical apparatus** — scholarly cards with sigla chips, variant type, and the prose note
- **Color-coded variants** — gold (aligned), sage green (minor / stylistic), rubric red (major / omitted / added)
- **Click-to-open tooltips**:
  - Greek tokens → Strong's number + lemma + morphology (STEP Bible TAGNT)
  - Peshitta tokens → triliteral root + sister roots + Hebrew / Arabic cognates ([Aramaic Root Atlas](https://aramaic-root-atlas.onrender.com))
- **Shift-click a variant token** → inline apparatus popover without leaving the view
- **⌘K / Ctrl-K search** across Greek, Latin, Syriac, English (WEB), variant type, or by reference (`13:14`)
- **Full keyboard navigation** (`←` `→` paginate verses, `⌘K` search, `Esc` close overlays)
- **Multilingual UI** — English (default), Spanish, Simplified + Traditional Chinese; localized URLs (`/es/`, `/zh-Hans/`, `/zh-Hant/`); first-visit auto-redirect from `Accept-Language`; settings cog in the topbar with sticky preferences (interface language, multi-gloss visibility, theme)
- **Multi-language verse glosses** — RV 1909 (Spanish) and CUV 1919 (Chinese, Simplified + Traditional) stack vertically above the alignment grid; toggle each on/off in settings
- **Public JSON API** — alignment artifacts, display-shape verse dicts, search, and corpus manifest at [/api/v1/](https://polyglotconcordance.com/api/v1/) ; CORS-open, edge-cached, OpenAPI-documented

## API

The same artifacts that power the rendered HTML viewer are exposed as a public, read-only, CORS-open JSON API. Five versioned endpoints under `/api/v1/`:

| Endpoint | Returns |
|---|---|
| [`/api/v1/manifest`](https://polyglotconcordance.com/api/v1/manifest) | Corpus metadata + witness list + variant vocabularies + benchmark stats |
| [`/api/v1/alignment/{book}/{chapter}/{verse}`](https://polyglotconcordance.com/api/v1/alignment/mark/13/14) | Canonical alignment JSON (verdicts, types, apparatus notes, confidence) |
| [`/api/v1/verse/{book}/{chapter}/{verse}`](https://polyglotconcordance.com/api/v1/verse/mark/13/14) | Display-shape verse (witnesses + variants + 4-language `gloss_map`) |
| [`/api/v1/search?q=...`](https://polyglotconcordance.com/api/v1/search?q=harmonisation) | Verse-level full-text search across all witnesses + variant types |
| [`/api/v1/openapi.json`](https://polyglotconcordance.com/api/v1/openapi.json) | OpenAPI 3.0 spec |

Plus [Swagger UI at `/api/docs`](https://polyglotconcordance.com/api/docs) and a human-readable [index at `/api/v1/`](https://polyglotconcordance.com/api/v1/).

```bash
# Discover the corpus
curl -s https://polyglotconcordance.com/api/v1/manifest | jq .

# Pull one verse's apparatus
curl -s https://polyglotconcordance.com/api/v1/alignment/mark/13/14 | jq .

# Just the non-aligned groups
curl -s https://polyglotconcordance.com/api/v1/alignment/mark/13/14 \
  | jq '.alignment[] | select(.verdict != "aligned") | {id, verdict, type, note}'
```

Full reference + response schemas + error envelope conventions: [**docs/api.md**](./docs/api.md).

## Methodology

Every verse is aligned by Anthropic's **Claude Sonnet 4.5** via the Messages Batch API. For each verse, Claude receives:

- The Greek, Syriac, and Latin tokens (whitespace-split)
- Per-Greek-token enrichment: Strong's number, lemma, morphology, English gloss (from STEP TAGNT)
- Per-Peshitta-token root data (from the Aramaic Root Atlas)

Claude returns a strict JSON structure: a list of alignment groups where each group ties one or more tokens from each tradition together and tags:

- **Verdict** — `aligned`, `minor`, `major`, `omitted`, `added`
- **Type** — `agreement`, `expansion`, `omission`, `substitution`, `harmonisation`, `word-order`, `construction`, `idiom`, `punctuation`, `grammar`, `lexical`, `gloss`
- **Note** — one or two sentences of apparatus-style prose for every non-aligned group (mean length ~296 chars)
- **Confidence** — Claude's self-reported confidence `[0, 1]`

All 678 verses × 8,206 alignment groups are stored as committed JSON in `data/alignments/mark/`. The running viewer has zero runtime LLM dependency.

### Methodology validation (and its limits)

We sanity-checked Claude's alignment reasoning against the **[Berean Interlinear Bible](https://berean.bible/)** on the narrow sub-task of Greek → English word alignment. Across all 673 Mark verses (6,175 scoring tokens), Claude agreed with Berean's scholarly glosses on **67.7%** of tokens.

The ~32% of non-matches are mostly **translation-word-choice differences** between Berean and the WEB (the two English translations involved in the comparison) — e.g. Berean "crowd" vs. WEB "people" for the same Greek ὄχλος — rather than alignment errors.

**What this benchmark means:**

- ✅ It's a **transferable sanity check**: Claude's alignment reasoning is consistent with an established scholarly interlinear on the sub-task we *can* measure (Greek→English). That rules out catastrophic failure modes and gives some evidence the broader 3-way alignments use the same reasonable logic.
- ❌ It does **not** directly measure the quality of Greek↔Peshitta, Greek↔Vulgate, or Peshitta↔Vulgate alignments — no ground-truth reference exists for those pairs. It also doesn't measure apparatus-note quality, variant classification accuracy, or type-tag correctness.

Reproduce it yourself: `python scripts/run_berean_benchmark.py --berean data/benchmarks/berean_mark_source.json --sample-size 673`

## Tech stack

- **Backend**: Python 3.10+, Flask 3, Jinja2 — single `app.py`, thin route layer; business logic + i18n + API blueprint in `translation_core/`
- **Frontend**: Server-rendered HTML + vanilla JavaScript + one CSS file. **No build step**, no framework.
- **i18n**: per-language JSON dicts in `translations/` (no Babel, no gettext); locale resolved by WSGI middleware that strips `/<lang>/` URL prefixes
- **API**: Flask Blueprint at `/api/v1/`, OpenAPI 3.0 spec served at `/api/v1/openapi.json`, Swagger UI at `/api/docs`
- **Interactivity**: htmx-friendly partial endpoints for per-verse swaps; `<script id="variants-data" type="application/json">` for the variant popover
- **Typography**: EB Garamond + Cardo (scripture body, Greek + Latin), Noto Sans Syriac (Peshitta), Noto Sans SC/TC (CJK glosses), Inter (UI chrome), JetBrains Mono (sigla / captions)
- **Data**: CSV corpora + per-verse JSON alignments, all committed. Total data footprint ~3 MB.
- **Tests**: **138 pytest cases** covering schema, converter, routes, search, benchmark, i18n, locale routing, gloss-CSV ingestion, and the API. `pytest -q` runs the full suite in < 1 second.
- **Deploy**: Render web service (Starter tier), custom domain `polyglotconcordance.com`, edge caching for static assets, GA4 + Google Search Console wired in.

## Quickstart

```bash
# 1. Clone
git clone https://github.com/Jossifresben/translation-alignment.git
cd translation-alignment

# 2. Python env + deps
python -m venv .venv
source .venv/bin/activate
pip install -r requirements-dev.txt

# 3. (Optional) Add your Anthropic API key — only needed if you want to
#    regenerate alignments or run the Berean benchmark yourself
cp .env.example .env
# edit .env and paste your key

# 4. Run tests
pytest -q     # 138 passing in <1 s

# 5. Run the viewer
python app.py
# → http://localhost:5020
```

No network calls at runtime. The Anthropic API key is referenced only by offline scripts in `scripts/`.

## Regenerating alignments

Everything is reproducible from source data + an API key:

```bash
# 10-verse pilot (sanity check — ~$0.05, ~2 min)
python scripts/generate_alignments.py --pilot

# Full Mark, Batch API (~$1.50, ~20 min wall clock, 50% batch discount)
python scripts/generate_alignments.py --full

# Regenerate a single verse
python scripts/generate_alignments.py --verse Mark 13 14

# Flag low-confidence verses for human review
python scripts/generate_alignments.py --report

# Re-run the Berean benchmark
python scripts/run_berean_benchmark.py \
  --berean data/benchmarks/berean_mark_source.json \
  --sample-size 673
```

## Re-ingesting the verse glosses

Each gloss CSV is reproducible from its USFX source (no manual editing):

```bash
python scripts/ingest_rv1909.py --download    # → data/corpora/rv1909.csv
python scripts/ingest_cuv.py --download --hans --hant
# → data/corpora/cuv_hans.csv, data/corpora/cuv_hant.csv
```

All three writers verify Mark-verse parity against `web.csv` and refuse to emit drift. (CUV's USFX hides Mark 7:16 and 15:28 in textual-criticism footnote markup; the ingester walks those out so the CSV matches WEB versification exactly.)

## What this app is good for

The underlying engine is a **multi-witness parallel-text viewer with a critical apparatus and a public JSON API**. Anywhere a text exists in more than one version, this tool can show it side-by-side with per-word alignment and annotated divergences — and let downstream tools fetch the data programmatically.

### Biblical scholarship

- **Text-critical study** — see where a Greek NT verse, its Peshitta translation, and its Vulgate rendering disagree, with each divergence typed (harmonisation, substitution, idiom, grammar change, etc.) and explained in one or two sentences.
- **Synoptic comparison** — once Matthew / Mark / Luke all ship, compare the same pericope across the three Synoptic gospels in three languages each.
- **Semitic-language parallel reading** — Peshitta next to Hebrew OT next to Targum Onkelos; root / sister-root tooltips surface cognate structure visibly.
- **Translation-technique study** — how does the Peshitta handle Greek participles? How does the Vulgate handle Hebrew infinitive absolutes? The typed apparatus makes this kind of question quickly answerable.
- **Harmonisation tracing** — when one tradition imports material from a parallel passage (e.g. Peshitta Mark 13:14 pulling "by Daniel the prophet" from Matt 24:15), the apparatus flags it explicitly.

### Teaching

- **Ancient-language pedagogy** — introductory Greek / Hebrew / Syriac / Latin students can hover any word for Strong's / lemma / morphology. The variant apparatus turns every verse into a textual-criticism lesson.
- **Comparative religion** — a neutral surface for showing how different canonical lineages transmit the same base text.
- **Critical-edition training** — readers learn to read a scholarly apparatus by clicking through real examples rather than deciphering the dense sigla of a printed NA28 / BHS.

### Translation work

- **Checking a new translation against ancient witnesses** — does a contemporary Spanish or Chinese rendering match the majority of ancient traditions or diverge meaningfully?
- **Informing committee decisions** — Bible translation teams can point to a specific divergence pattern (e.g. "MT + LXX + Peshitta all read X; only Vulgate reads Y") in one clickable reference.

### Reader-facing discovery

- **Scripture reading with a critical dimension** — readers can see that a familiar phrase has a contested history without opening a textbook.
- **Liturgical comparison** — Eastern Orthodox liturgies use Slavonic + Greek Byzantine; Catholic uses Vulgate; churches of the East use Peshitta. All three surface-able side by side.

### Programmatic / NLP

- **Open dataset for text-critical NLP** — fetch every alignment group via [`/api/v1/alignment/mark/{ch}/{v}`](https://polyglotconcordance.com/api/v1/alignment/mark/13/14) for downstream analysis (variant-type classification, harmonisation detection, translation-technique modeling).
- **Composable with other tools** — CC BY data + CORS-open API means anyone can build a phylogenetic study, a benchmark dataset, a parallel-corpus visualization, etc., on top.

## Known limits

See [`known-issues.md`](./known-issues.md) for the complete list. Highlights:

- Versification: Vulgate chapter-verse numbering differs from NA28 in some places. We've remapped Mark 9 and noted Mark 4:40–41; other chapters and books will need the same treatment as coverage expands.
- 29 Mark verses have alignment confidence below 0.30 (mostly short or compositionally unusual verses). They're flagged for human review via `scripts/generate_alignments.py --report`.
- No ground-truth reference exists for the Peshitta or Vulgate alignment quality — only the Greek→English sub-task is externally benchmarked.
- The apparatus prose is English-only in the pilot. Spanish + Chinese translation of the ~2,600 apparatus notes is scheduled as a separate Phase-2 Claude batch with a field-aware prompt and a scholar-reviewed sample.

## Inspiration

The parallel-columns layout and the minor / major color-coding convention come from the **bible-mt5** parallel viewer built by [Dr. Zhan Chen](https://staff.uic.edu.cn/zhanchen/en) (United International College / BNU-HKBU UIC, Zhuhai), who has framed his work as a "concordance initiative with alignment to the word level." Polyglot Concordance extends that approach with a critical apparatus on every divergence and a programmatic JSON API. Dr. Chen's own scholarship focuses on the Peshitta of Isaiah (Harvard NELC, 2020) and Chinese Bible translations.
